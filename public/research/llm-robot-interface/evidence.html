Methods and trial records

Experimental protocol, cohort accounting, physical measurement accuracy, and timing definitions.

Trevor Kwan November 19, 2026

Experimental setup

Every trial ran on the same physical desk using an isolated, memoryless actor session per episode. Both conditions shared the same hardware, camera calibration, safety supervisor, and task prompt, differing only in whether the model could call a read-only Python interpreter between robot moves. All harness code, calibration matrices, and raw episode logs are published in trevorkw7/llm-robot-interface (run analysis/reproduce_summary.py to recompute the summary tables directly from disk).

Implementation details

A core design goal was separating the experimental harness from the model under test so that neither condition could leak state across runs, bypass physical limits, or turn the Python interpreter into a closed-loop controller.

  • Single-executor motor supervisor (src/supervisor.py): All physical actuation goes through one local HTTP service on 127.0.0.1 backed by an explicit state machine (IDLE → HEALTH → PREP → RUN → SCORE → RESET plus a persistent STOPPED latch). Each phase issues a scoped lease token so only the active role (actor, reset, or qualify) can command the arm. Every move request carries an idempotent cmd_id (at-most-once execution with safe retry replay) and is validated before motion against joint envelopes, per-move step caps, peak smoothstep speed (1.5 · |Δq| / duration_s ≤ 30°/s), and swept-body workspace keep-outs (src/kin.py).
  • Frozen MCP actor bridge (src/actor_mcp.py): Exposes exactly the six shared robot tools over newline-delimited JSON-RPC 2.0. At startup it reads actor_limits from the supervisor’s GET /state endpoint and injects those exact numbers into the tool schemas so prompt documentation and runtime enforcement never drift.
  • Read-only bwrap Python sandbox (src/compute_mcp.py, src/sandbox.py): Condition B’s interpreter runs inside a Linux bubblewrap namespace with no network, no supervisor URL or lease token, no subprocess spawning, per-call CPU limits, and bounded /work and /tmp quotas. It can read only immutable observation snapshots already returned to the actor and the shared robot specification files, ensuring every physical move still passes through move_joints.
  • Overhead survey, reset, and blinded grading (src/tsurvey.py, src/reset3.py, src/grader.py): After each finish and three-second hold, the wrist camera flies to a fixed overhead pose and diffs against an empty-tray reference image to segment the carton silhouette regardless of color, mapping the fitted rectangle into robot base-frame (x, y, yaw) via a self-calibrated arm-as-ruler affine transform. All episode logs, saved LLM Python scripts, adjudication outcomes (OUTCOMES.jsonl), and the four-day engineering log (DECISIONS.md) are archived in the repository.

Cohort accounting

Each matched pair ran back-to-back on the same arm from a camera-verified starting layout with identical target coordinates and prompt text. A pair entered the primary comparison only when both starts passed the automated start gate, both episodes reached a scored finish, and the host computer delivered the assigned tools without interruption. Poor grasps, buggy model-written Python scripts, and script timeouts all remained in the dataset.

Across the pilot and main cohorts, 30 precision sessions launched and 27 reached a scored finish (13 tools-only, 14 with Python), yielding 12 complete matched pairs. During post-hoc log auditing, I discovered that a host disk-space watchdog (<1 GiB free) had repeatedly wiped the Python interpreter mid-episode during one main pair (p05). Setting aside both halves of that pair left 11 clean matched pairs (five pilot, six main) for the primary comparison.

Measurement and grading

To pass, the green Fuji Superia 200 carton had to rest flat on one of its long faces inside the shallow tray, with its center within 15 mm of the target coordinate, its long axis within ±15° of the target axis (180°-symmetric), no overhang past the tray rim, and the gripper withdrawn clear throughout a fixed three-second terminal evidence interval.

Final carton poses were measured with a calibrated two-view overhead wrist-camera survey (src/tsurvey.py), which had 3.6 mm held-out RMS error along the independently checked axis. An independent, blinded Claude Opus 5.5 grader (src/grader.py; results in OUTCOMES.jsonl) adjudicated each episode from the terminal camera evidence without seeing the tool condition, and a 3,038-frame terminal image audit verified gross on-tray placement across all 45 finished tray runs (no separate human re-grade of every packet).

Broken down by cohort, mean center error was 4.86 mm without Python versus 7.76 mm with Python across the five pilot pairs, and 6.35 mm versus 6.70 mm across the six main pairs (5.67 mm vs. 7.18 mm pooled across all 11 pairs). Because that 1.51 mm difference sits inside the 3.6 mm survey precision and is driven by a systematic wrist-angle offset at Goal G3, the pooled averages do not establish an accuracy advantage for either setup.

Exclusions and sensitivity

Before the host disk-space fault was discovered, the prespecified main-study analysis included all seven complete main pairs, giving mean center errors of 6.14 mm without Python and 6.01 mm with Python. Excluding both halves of the affected pair reverses the sign of that small difference (6.35 mm vs. 6.70 mm), confirming that the two setups were indistinguishable on raw mean center error. Across all pairs, the original pooled time saving was 2.43 minutes; after the clean exclusion it is 2.59 minutes (10.61 vs. 8.02 minutes).

A separate three-pair open-loop stress test (limiting the arm to a single initial camera look) used a different prompt and only had one pair with uninterrupted host service. It is excluded from the 11-pair precision comparison and documented separately in the build log.

Timing, tokens, and cost accounting

First-move latency: Measured from the first model request until the motor supervisor returns its reply to the first joint command (279 s without Python vs. 206 s with Python). One tools-only first request was rejected under the normal speed limit; counting only completed arm moves yields a 71.7-second advantage for Python across the 11 pairs. Requested joint motion time sent to the controller averaged 36.5 s without Python and 35.2 s with Python (total wall-clock arm motion including settling and overhead averaged ~1.1 minutes per run).

Tokens and API cost: Full-session totals include every turn through the final finish() response. Across the 11 pairs, runs averaged 55,045 output tokens without Python versus 36,479 with Python, 107.6k versus 110.2k cache-write tokens, and 483k versus 1.44M cache-read tokens. At fixed list prices ($40/M output, $16/M cache write, $0.20/M cache read), actor API cost averaged $4.02 without Python and $3.51 with Python across all 11 pairs ($4.08 vs. $3.39 across the six main pairs). Automated resets and blinded Opus grading are accounted for separately.

Reasoning pauses: The client logged 85 reasoning blocks without Python (median 26.8 s) and 249 with Python (median 5.3 s). Because the API does not expose raw chain-of-thought text, those durations measure inference wall time; all behavioral claims in the main article are grounded in visible model messages, saved prog_*.py scripts, and logged joint commands.

Video clocks and target overlay

In the side-by-side demonstration (Pilot 1), the two runs executed back-to-back on the same arm and are aligned at t = 0 (first model request). On the activity timeline, gold marks model inference, blue marks Python execution, green marks accepted arm motion, purple marks camera captures, and gray marks overhead. The compact edit speeds up idle waiting equally on both sides while slowing down during physical arm motion; full constant-speed recordings are available directly as real-time MP4 and constant 4× MP4.

The yellow 15 mm ring and axis ticks drawn on the tray in the video are a post-hoc pinhole projection of the base-frame goal coordinate onto the front camera view. No physical mark appeared on the tray during any trial.
